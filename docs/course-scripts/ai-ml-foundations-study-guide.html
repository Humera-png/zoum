Part 1 — Week by week

Module 1 — Python for AI & Data Work

WEEK 1

Python fundamentals

Covers: variables, if/else, loops, functions, and running code in a notebook.

Core idea: a program is just a sequence of instructions the computer follows in order — everything else is built from that.

Practice: write a function that takes a list of numbers and returns the average, without using a library.

WEEK 2

NumPy & Pandas

Covers: arrays, DataFrames, loading a CSV with pandas.read_csv(), filtering rows, grouping, handling missing values.

Core idea: almost all real data work is Pandas — load it, look at it, clean it, ask it questions.

Practice: load a public CSV dataset and answer three questions about it using filtering and grouping (e.g. "which category has the highest average value?").

WEEK 3

Exploring & visualizing data

Covers: Matplotlib/Seaborn charts, spotting outliers and missing data visually.

Core idea: never model data you haven't looked at first — a chart reveals problems a table hides.

Practice: make one histogram and one scatter plot from your Week 2 dataset; write one sentence on what each reveals.

Module 2 — Core Machine Learning Concepts

WEEK 4

What machine learning actually is

Covers: supervised vs. unsupervised learning, training data vs. test data, overfitting.

Core idea: a model that scores perfectly on data it already saw has usually just memorized it — the only score that matters is on data it's never seen.

Quick check: if a model gets 99% on training data and 60% on test data, what's wrong? → It's overfitting: it memorized the training set instead of learning a general pattern.
WEEK 5

Core algorithms

Covers: linear regression, logistic regression, decision trees — conceptually, then trained with scikit-learn:

from sklearn.linear_model import LogisticRegression
model = LogisticRegression()
model.fit(X_train, y_train)
predictions = model.predict(X_test)

Practice: train a logistic regression on the Week 2 dataset to predict one column from the others.

WEEK 6

Evaluating a model honestly

Covers: accuracy, precision, recall, the confusion matrix.

Core idea: on imbalanced data (e.g. 95% of cases are "normal"), a model that always guesses "normal" gets 95% accuracy while being useless. Precision and recall catch this; accuracy alone doesn't.

Practice: compute the confusion matrix for your Week 5 model and explain what each of its four numbers means in plain English.

Module 3 — Real Datasets, AI APIs & Final Project

WEEK 7

A real, messy dataset + calling an AI API

Covers: taking a genuinely messy dataset through clean → explore → model, and calling an AI API (OpenAI/Anthropic) from Python to use its output inside code, not a chat window.

import anthropic
client = anthropic.Anthropic(api_key="...")
response = client.messages.create(
    model="claude-...",
    messages=[{"role": "user", "content": "Summarize this row of data: " + str(row)}]
)

Practice: pick your messiest column so far and write a function that cleans it.

Part 2 — Glossary

TermPlain-language meaning
ModelA program that's learned a pattern from data, instead of being told the rule directly
Training dataThe data a model learns from
Test dataData held back so you can check the model on examples it's never seen
OverfittingA model that memorized training data instead of learning a general pattern
FeatureOne input column a model uses to make a prediction
LabelThe correct answer a supervised model is trying to predict
Supervised learningLearning from data that already has the correct answers attached
Unsupervised learningFinding structure in data that has no correct answers attached
Accuracy% of predictions that were correct — misleading on imbalanced data
PrecisionOf everything the model called "positive," what % actually was
RecallOf everything that actually was "positive," what % the model caught

Part 3 — Final project guide

Your final project should show you can take a problem from raw data to a working, evaluated model.

  1. Pick a dataset that genuinely interests you (public datasets from sources like Kaggle work well) — something you'd actually want the answer to.
  2. Clean and explore it using what you built in Weeks 1–3.
  3. Train a model using what you built in Weeks 4–6.
  4. Evaluate it honestly — report accuracy and precision/recall, and say plainly where the model is weak.
  5. (Bonus) Call an AI API somewhere in the project — e.g. to generate a plain-English summary of your model's findings.
  6. Present it in Week 8: what the problem was, what you built, what it got right and wrong, and what you'd try next.
