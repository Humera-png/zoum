Part 1 — Core concepts

1.1 Automation is just "when X happens, do Y"

Every automation, however complex, is a chain: something starts it, then steps run in order. If you can describe a task as "first this, then this, then this," you can automate it. The skill this course builds is seeing your work as chains.

1.2 What n8n is

n8n is a visual workflow tool. Instead of writing a program, you place boxes called nodes on a canvas and connect them with lines. Each node does one small job. n8n runs the chain for you every time the trigger fires.

  • Canvas — where you build. Left → right is the order things run.
  • Node — one step. Click it to open its settings on the left; after it runs, its output data shows on the right.
  • Execution — one run of the workflow. The Executions tab keeps a history of every run and what each node did.
  • Active / inactive — a workflow only runs on its own (from a webhook or schedule) when you toggle it Active, top-right. While building, you just click "Test workflow".

1.3 Triggers — how a workflow starts

A workflow starts with a trigger node. Start with one; you can add more later.

TriggerFires when…Use for
Manual Triggeryou click "Test workflow"building and testing
Webhookan HTTP request hits its URLa form submission, another app calling you
Schedule Triggera time you set (e.g. every hour)reports, recurring checks, reminders

The Webhook node gives you two URLs: a Test URL (works while you've clicked "Listen for test event") and a Production URL (works once the workflow is Active). In class we use the Test URL.

1.4 Nodes and data flow

When a node runs it produces output data — a list of items, each a JSON object. The next node receives that as its input. So any node can use anything an earlier node produced. Data looks like this: 

{
  "name": "Priya",
  "email": "priya@example.com",
  "message": "Do you take on inventory automation for a mid-size distributor?"
}

1.5 Expressions — using a value from an earlier step

To pull a value from earlier in the chain, switch a field to Expression mode and write:

{{ $json.message }}
  • $json — the current input item's data
  • .message — the field you want
  • field name with a space: {{ $json["field name"] }}
  • reach a specific earlier node: {{ $('Webhook').item.json.email }}

This is the only piece of syntax in the whole class. Quick check: with the JSON above, what does {{ $json.name }} return?  →  Priya

1.6 Credentials

API keys and logins are stored once as credentials, separate from any node. You create a credential (e.g. "OpenAI account"), then any node picks it from a dropdown. After you save it the key is never shown again and never appears in the workflow itself — so a workflow is safe to share or export.

Part 2 — Guided build: AI-powered lead follow-up automation

Goal: when a new lead arrives, an AI reads their message, drafts a personal reply, and sends it.

Webhook (lead arrives)  →  AI node (draft reply)  →  Send (email / Slack)
STEP 1

Webhook trigger

  1. New workflow. Add a Webhook node.
  2. Set HTTP Method to POST.
  3. Copy the Test URL.
  4. Click Listen for test event — the node is now waiting.
STEP 2

Send a test lead

Send this request (the instructor shows how — browser console, or a shared tool):

POST  <your test URL>
Content-Type: application/json

{ "name": "Priya",
  "email": "priya@example.com",
  "message": "Do you take on inventory automation for a mid-size distributor?" }

The Webhook node turns green and shows the data. You now have $json.name, $json.email, $json.message available to every node after it.

STEP 3

AI node

  1. Add an OpenAI or Anthropic node (operation "Message a model"), or a Basic LLM Chain.
  2. Select the credential (sandbox key provided in class).
  3. Model: a small, fast one is fine for this.
  4. User message / prompt, in Expression mode:
Write a warm, specific 3-sentence follow-up reply to this inquiry.
Do not invent details or make promises about pricing or timelines.

Inquiry: {{ $json.message }}
  1. Run the node. Read the reply it generated.
Why the "do not invent" line matters: the prompt tells the AI what not to do. Without it, a model will happily make up a price or a delivery date. Telling it the boundaries is part of the job.
STEP 4

Send the reply

Use whichever the class is set up for:

  • Gmail node → "Send" → To: {{ $('Webhook').item.json.email }}, Subject: Thanks for reaching out, Message: the AI node's output.
  • Slack / Discord node → post to a channel, Text: the AI node's output. (Best stand-in when email credentials aren't available.)
STEP 5

Test the whole chain

Send 2–3 different leads with different messages. Confirm the AI writes a genuinely different, relevant reply each time — not a template with a name swapped in.

What you just learned: the trigger → AI decision → action pattern. Order processing, support triage, and lead scoring are the same three pieces with different nodes.

Part 3 — The three automation patterns

Almost everything you will build is one of these three shapes. When you have a task, first ask which one it is:

  1. Trigger → AI decision → action — lead follow-up, support triage, content drafting
  2. Trigger → fetch → transform → store — reporting, syncing data between apps, enrichment
  3. Schedule → check → act if needed — monitoring, reminders, recurring jobs

Part 4 — Practice exercises

Do these after the session. Each one builds on the last.

  1. Echo bot. Webhook → a Set / Edit Fields node that outputs Hello {{ $json.name }}. Test it.
  2. Auto-categorize. Webhook (a support message) → AI node that replies with only one word: billing, technical, or other.
  3. Daily quote. Schedule Trigger (once a day) → HTTP Request to a free public quotes API → Slack / Discord post.
  4. Lead router. Take your Part 2 build. Add an IF node after the webhook: if message contains "urgent", send to one channel; otherwise the normal one.
  5. Your task. The repetitive task you brought to class. Decide which of the three patterns it is, write the node chain on paper, then build it.
