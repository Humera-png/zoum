0:00 – 0:15 · OPEN

Framing & goal-setting

Explanation to give the room: Start with your own story, not a slide. Everything you're about to teach was built to solve a real problem, not learned from a course: LeadFlowTool (lead follow-up), an order-processing pipeline, a lead-generation pipeline, a supply-chain automation — all running in production today, all built in n8n. Say this plainly: "I'm not going to teach you a tool. I'm going to teach you the exact three-piece pattern behind every one of those systems, and by the end of today you will have built one yourself."

Warm-up (do this out loud, don't skip it): ask "Who here has a task at work they do the exact same way, every single time?" Take 2–3 answers. Write ONE of them on the board — you will come back to it at 2:50 as the seed for their 7-Day Build Plan. This does two things: it proves the room already has automation candidates without knowing it, and it gives you a personal hook to close the class with later.

Set the goal explicitly, word for word: "By 2:35 today, you will have personally built and tested one real, working automation. Not watched me build one. Built one, on your own laptop, with your own hands on the keyboard."

If asked: "Do I need to know how to code for this?"

No. Answer immediately and move on: "n8n is visual — you connect boxes, you don't write a program. The only syntax in the entire class is one small expression, and we drill it until it's automatic." Don't over-explain this early; it lands better once they've seen the canvas.

0:15 – 0:45 · WHAT N8N ACTUALLY IS

The mental model, why n8n, and the interface

Definition (say this, then draw it): "n8n is a visual workflow tool. Instead of writing a program from scratch, you place boxes called nodes on a canvas and connect them with lines. Each node does exactly one job." Draw on the board: Trigger → Action → Action → Action. Underline that this is the whole idea — a workflow is just that chain, and n8n runs it automatically every time the trigger fires. Every single thing built today, and everything in the enhanced program afterward, is a variation of this one diagram.

Why n8n and not Zapier or Make (someone will ask this): three concrete reasons, in this order because the third is the one that matters for this class: (1) self-hostable, so there's no vendor lock-in; (2) no per-task pricing wall, so a workflow that runs a thousand times a day doesn't suddenly cost a thousand times more; (3) — the important one — n8n has first-class nodes for calling AI models directly inside a workflow, which is the entire point of today's build.

Interface walkthrough (you drive, room watches, nobody touches their laptop yet): open a blank n8n canvas. Point out, in order: the canvas itself (empty space where nodes go), the node panel (click + to search and add a node), the top-right Active toggle (off while building — a workflow only runs on its own once this is on), and the Executions tab (a history of every run, which node did what). Add a Manual Trigger node, add a Set node after it, connect them, click Test workflow, and show the green checkmark and the output panel on the right. This single minute of demo removes 80% of the "where do I click" questions later.

Common mistake to pre-empt: people confuse "Test workflow" (runs it once, right now, for you to see) with "Active" (makes it run automatically forever from its trigger). Say this distinction out loud now — it prevents confusion in the break-out build later.
0:45 – 1:20 · CORE BUILDING BLOCKS, HANDS-ON

Everyone builds alongside you now — triggers, data flow, expressions, credentials

This is the first block where every attendee opens their own n8n account and types along. Go slowly here; rushing this block is the single biggest cause of people getting lost in the 1:30 build. Four concepts, in this order:

1. Triggers

Explain the three types with one line each: Manual Trigger fires when you click "Test workflow" (good for building); Webhook fires when an HTTP request hits its URL (good for "something happened elsewhere and told us"); Schedule Trigger fires on a timer (good for "check this every hour"). Today's build uses a Webhook, because a lead form submission is exactly "an HTTP request telling us something happened."

Live, together: everyone adds a Webhook node, sets HTTP Method to POST, and clicks Listen for test event. Point out the two URLs it shows — Test URL (works only while listening, what we use today) and Production URL (works once the workflow is Active, mention it exists, don't dwell). Everyone copies the Test URL, then sends one request to it (from a browser console, or a shared tool you provide):

POST <test URL>
Content-Type: application/json

{ "name": "Priya", "email": "priya@example.com",
  "message": "Do you take on inventory automation for a mid-size distributor?" }

The node turns green and shows this JSON in its output panel. Point at the screen and say: "This is now data. Every node after this one can reach into it."

2. Nodes & data flow

Explain: "A node's output becomes the next node's input — always, no exceptions. That's the entire data model of n8n." Add an HTTP Request node after the webhook (no real request needed yet — just show that its input panel already contains the webhook's JSON). This is the moment people mentally connect "boxes on a canvas" to "a real program."

3. Expressions — the one syntax concept in the whole class

Introduce it directly: "To pull a value out of a previous node, you write an expression." Show the syntax on the board first, then in the tool:

{{ $json.message }}

Break it down piece by piece, out loud: $json means "the data arriving at this node right now"; .message is the specific field you want. If a field name has a space in it, show the alternative: {{ $json["field name"] }}. If you need a value from a node further back than the immediately previous one, show: {{ $('Webhook').item.json.email }} — name the node in quotes, then walk down to the field.

If asked: "Why does the field sometimes show as undefined?"

Almost always a typo or wrong case in the field name — say this now so it's not a mystery later: "Click the node and look at its actual output panel; copy the field name exactly from there instead of typing it from memory."

Drill it: ask the room, using the JSON sent above, "what does {{ $json.name }} return?" Wait for someone to say "Priya" out loud before moving on. This is the only real "test" in the class and it matters — expressions are used constantly for the rest of the day.

4. Credentials

Explain briefly, this doesn't need much time: "API keys are saved once, as a credential, separate from any single node. Any node can then select that credential from a dropdown. Once saved, the key itself is never shown again — so a workflow is safe to export or share without leaking a secret." No hands-on step here yet; credentials get created live in the next block when the AI node needs one.

Checkpoint — do not move on until this is true for most of the room: everyone has a Webhook Trigger, has sent it a test request, and can see the JSON in its output panel. Walk the room and check hands, don't just ask "everyone good?" out loud.
1:30 – 2:35 · THE REAL BUILD

An AI-powered lead follow-up automation, built by everyone from an empty canvas

Set the shape on the board before anyone touches a keyboard:

Webhook (a lead arrives)  →  AI node (draft a reply)  →  Action (send it)

Say explicitly: "This is the same three-piece pattern from this morning's diagram, with real nodes in each slot. Once you can build this, you can build order processing, lead scoring, support triage — same shape, different nodes."

Step 1 — Trigger (10 min)

Everyone builds a fresh Webhook node exactly as in the previous block (POST, Listen for test event, copy the Test URL). This repetition is deliberate — the goal is that by the third time they've set up a webhook today, it's automatic.

Step 2 — Send a realistic test lead (5 min)

POST <test URL>
Content-Type: application/json

{ "name": "Priya", "email": "priya@example.com",
  "message": "Do you take on inventory automation for a mid-size distributor?" }

Confirm out loud that everyone sees the green checkmark and the JSON before moving to the AI node — this is the step most likely to have a straggler, and the AI step is much harder to debug if the webhook data isn't actually there yet.

Step 3 — AI node (20 min, the heart of the class)

Add: an OpenAI or Anthropic node, operation "Message a model" (or a Basic LLM Chain node — either works, pick whichever the room's sandbox key supports). Select the sandbox credential you're providing for the class. Model: any small, fast one — this doesn't need to be the most capable model available, it needs to be fast enough that people aren't waiting.

The prompt — write this on the board first, then type it together, in Expression mode:

Write a warm, specific 3-sentence follow-up reply to this inquiry.
Do not invent details or make promises about pricing or timelines.

Inquiry: {{ $json.message }}

Explain why the second line exists — this is the single most important teaching moment in the class: "A language model will happily invent a price or a delivery date if you don't tell it not to. Writing the boundary into the prompt is not optional politeness — it's the actual engineering. The prompt is the interface; what you put in it is what governs the system's behavior." Run the node. Read the output out loud. Ask the room: "Is this templated, or did it actually respond to what Priya asked?" — get them to notice it referenced "inventory automation" and "distributor" specifically.

Common mistake: forgetting to switch the prompt field into Expression mode before typing {{ $json.message }} — it gets sent as a literal string instead of being evaluated. If someone's AI node output looks confused or literally contains curly braces, this is almost always why.

Step 4 — Action: send the reply (10 min)

Whichever the room has credentials for:

  • Gmail node → Send → To: {{ $('Webhook').item.json.email }}, Subject: Thanks for reaching out, Message: the AI node's output field.
  • Slack/Discord node → post to a channel, Text: the AI node's output. This is the more reliable option for a room full of people without pre-set-up email credentials.

Step 5 — Test the whole chain (15 min)

Send 2–3 different fake leads with genuinely different messages through the same webhook. Project one person's screen and read the AI's replies out loud for each — the goal is for the room to hear, not just see, that the tone and content actually change per message.

Step 6 — Name the pattern (5 min)

Say this explicitly, it's the payoff line of the whole class: "What you just built is trigger → AI decision → action. Order processing is trigger → AI decision → action. Lead scoring is trigger → AI decision → action. Support triage is trigger → AI decision → action. The nodes change. The shape doesn't."

Give the room 15–20 minutes inside this block to actually build it themselves rather than only watching one demo — circulate, don't just present. This is where the real learning happens.
